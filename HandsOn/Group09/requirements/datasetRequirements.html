3. D1 – Municipal parking facilities and number of spaces

R1. Smart city domain ✔

The dataset belongs to the urban mobility and public infrastructure domain. Municipal parking is part of the city's transport infrastructure and provides information that can be used to understand and explore parking resources within Madrid.

R2. Available as CSV ✔

The selected distribution is available as a CSV file: inventario_pars_agos_2026.csv. It can therefore be included directly in the project's csv/ directory and processed before its transformation into RDF.

R3. Open license ✔

The Madrid open-data portal publishes the municipal parking data under an open-data license that permits reuse subject to the applicable attribution conditions. The source and license information will be preserved when the data are redistributed and transformed into RDF.

R4. Linkable to real-world entities ✔

Parking facilities represent concrete real-world infrastructure. Their identifying and geographic information can be used to connect them with geographic entities such as Madrid districts, streets, locations and external geographic datasets.

Information Real-world entity Potential Linked Data connection
Parking identifier / name Municipal parking facility Stable RDF resource representing the facility
Location / address Geographic location and street OpenStreetMap, GeoNames or municipal geographic resources
District Madrid administrative district External administrative/geographic entities
Number of spaces Parking capacity Property of the corresponding parking facility

R5. Documentation ✔ High

The dataset is accompanied by information describing the municipal parking data. The documentation can be used to interpret the available fields and understand the meaning of the parking inventory information before the RDF transformation.

R6. Multiple data sources ◐

D1 is a Madrid City Council dataset. It becomes part of a multi-source Linked Data application when combined with D2 and external geographic datasets.

4. D2 – Municipal parking historical occupancy

R1. Smart city domain ✔

The dataset belongs to the urban mobility domain. Historical parking occupancy provides information about how municipal parking facilities are utilized over time. Such information can support the exploration of parking demand and urban mobility patterns.

R2. Available as CSV ✔

The historical occupancy dataset is distributed as CSV files. The project contains several annual distributions, represented by the 300346-*.csv files, together with ocupacionesaparcamientos2.csv.

These files are treated as different temporal distributions of the same dataset. Keeping the annual files in the project makes it possible to analyze occupancy over multiple years.

R3. Open license ✔

The dataset is published through the Madrid open-data portal under an open-data license that permits reuse subject to the applicable attribution requirements. The source and license information will be retained in the RDF publication.

R4. Linkable to real-world entities ✔

Historical occupancy observations can be linked to the concrete parking facilities described in D1. The parking identifier or other facility information provides the basis for connecting an occupancy observation to its corresponding real-world parking facility.

Information Linkable entity Use in the application
Parking identifier / name Municipal parking facility in D1 Connect occupancy observations with parking capacity and location.
Year and month Temporal entity Display historical occupancy trends.
Occupancy value Parking utilization observation Generate charts and compare facilities.
Parking capacity from D1 Parking facility capacity Compare occupancy with the number of available spaces.

R5. Documentation ✔ High

The project includes documentation concerning the municipal parking data structure. This documentation can be used together with the CSV distributions to interpret the occupancy information and construct the RDF representation.

R6. Multiple data sources ◐

D2 comes from the same Madrid open-data ecosystem as D1, but the two datasets provide complementary information: D1 describes parking facilities and capacity, while D2 describes their historical utilization. Additional external geographic data can be used to increase the number of independent sources.

5. How the datasets are linked

D1 ↔ D2: The parking inventory and historical occupancy datasets are linked through the identifier and/or identifying information corresponding to the same municipal parking facility.

D1 → Geographic entities: The location and address information of parking facilities can be used to connect them with geographic resources such as streets, districts and external geographic datasets.

D2 → D1: Each historical occupancy observation can be represented as an observation associated with a parking facility in D1. This allows occupancy history to be combined with the facility's location and capacity.

Parking facilities → External Linked Data: Geographic and administrative information can be used to connect the parking resources to external Linked Data sources such as OpenStreetMap, GeoNames or Wikidata, where suitable matching entities are available.

6. Discussion of the optional requirements

R5 – Documentation

High degree. The selected Madrid municipal parking datasets are accompanied by official dataset information and documentation. This provides a basis for understanding the data and transforming the CSV distributions into RDF.

R6 – Multiple data sources

Medium degree. The application combines two complementary datasets: a parking inventory and historical occupancy data. Both originate from the Madrid City Council open-data ecosystem, so they do not constitute completely independent publishers.

The Linked Data graph can nevertheless be extended with an external geographic source, such as OpenStreetMap, GeoNames or Wikidata. Such a source would provide additional information about the real-world geographic entities associated with the parking facilities.

7. Conclusion

Both selected datasets satisfy the mandatory requirements R1–R4. They belong to the smart-city and urban mobility domain, are available as CSV, are published as open data, and contain information that can be connected to real-world parking and geographic entities.

D1 provides the description and capacity of municipal parking facilities, while D2 provides their historical occupancy. Combining them creates a coherent data model for the proposed Madrid Smart Parking Explorer and provides a clear basis for subsequent RDF transformation and Linked Data publication.

R5 is satisfied to a high degree because official documentation is available. R6 is satisfied to a medium degree because the selected datasets are complementary but originate from the same municipal open-data ecosystem. Linking the parking facilities with an external geographic dataset would strengthen the multi-source aspect of the resulting knowledge graph.

Analysis

1. Analysis of the Data Source

The source is the City of Madrid dataset Historical Occupancy of Public Municipal Parking (dataset 300346) . It contains monthly occupancy measurements for public municipal parking facilities. The local copy consists of eight semicolon-separated CSV files covering 2019 through September 2026.

Format and Size

  • Format: CSV encoded as UTF-8 with a semicolon (;) separator.
  • Decimal notation: comma decimal separator; occupancy values include a percent sign.
  • Valid observations: 4,754 non-empty monthly records.
  • Coverage: 57 parking identifiers and 12 district codes.
  • Observation key: parking identifier, year and month. No duplicate keys were found.
  • Completeness: the 12 meaningful columns contain no missing values.

Column Value Analysis and RDF Mapping

The classifications below distinguish nominal categories (labels with no natural order), ordinal values (ordered categories), and quantitative or cardinal values (measurements for which arithmetic is meaningful). Cardinalities and ranges are calculated from the 4,754 non-empty source rows before normalization. Consequently, the raw numeric ranges include the outliers discussed in the data-quality section.

Data Quality and Transformation

  • The quoted column headings contain line breaks. A CSV parser must be used instead of splitting physical lines.
  • The source misspells CÓDIGO PAR as CÓDIDO PAR; it is interpreted as the parking identifier.
  • The files for 2019-2023 contain a thirteenth descriptive column whose data values are empty. It will be discarded.
  • Three completely blank records will be ignored.
  • Parking types will be normalized: ROT to ROTACIONAL and MIX to MIXTO.
  • District names will be trimmed and normalized to their accented forms, for example CHAMBERI to CHAMBERÍ.
  • Decimal commas will be converted to decimal points and percent signs removed before creating typed literals.
  • Thirty parking identifiers have more than one historical capacity. Therefore, the number of spaces is attached to each monthly observation rather than treated as an unchanging facility value.
  • The source contains implausible outliers, including negative values and occupancy percentages above 100%. These records will be preserved for traceability but flagged during transformation instead of silently corrected.

Publisher: Directorate General for Planning and Mobility Infrastructure

The dataset is published under the Creative Commons Attribution 4.0 International (CC BY 4.0) license.

  • Give appropriate credit to the creator or rightsholder.
  • Include a copyright notice when provided.
  • Provide a reference to the CC BY 4.0 license.
  • Provide a URI or hyperlink to the original licensed material when reasonably possible.
  • Indicate if modifications were made to the original material.
  • Indicate that the material is licensed under CC BY 4.0.

For the dataset generated from the original data, we will use the CC BY 4.0 license as well. This preserves the source attribution requirement while allowing the RDF dataset to be copied, redistributed and adapted. The generated dataset will credit the City of Madrid, link to the original dataset and license, and state that the source was cleaned and transformed to RDF by Group 13.

3. Resource Naming Strategy

All resources use the custom domain parking.linkeddata.upm.es. Ontology terms, properties and individuals have independent paths. Individual paths also identify the class of resource, preventing identifier collisions.

Class and property local names follow lower camel case: class names start with a capital letter and property names start with a lowercase letter. Identifiers are taken from stable source codes where available. The month in an observation URI is zero-padded to two digits.

4. Lightweight Ontology

The ontology represents four classes:

  • ParkingFacility: a municipal parking facility.
  • ParkingType: the normalized category of a parking facility.
  • District: a Madrid district; this class can be linked to external geographic entities.
  • OccupancyObservation: the measurements for one parking facility in one month.

A parking facility is linked to its district and parking type, and to its monthly observations. Each observation links back to its parking facility and contains its year, month, capacity, calculation days, average vehicles per day, overall occupancy and daytime occupancy. Every property has exactly one domain and one range in the ontology.

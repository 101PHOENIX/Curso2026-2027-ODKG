Dataset & Licensing Analysis

1. Dataset Analysis

We analyzed two datasets from the Chicago Data Portal: CPD_Facilities and CPD_Park_Art.

1.1. Facilities Dataset

Each row is one facility (a playground, a tennis court, a gymnasium, etc.) located in a park.

  • Quantities: 4,467 rows and 9 columns.
  • Null Values: Very clean data. The only missing values are one blank FACILITY_N and one blank FACILITY_T, and both belong to the same row (OBJECTID_1 4482, Gately Park). That row describes no facility and will be removed.
  • Unique Values: 549 distinct park numbers (PARK_NO) but 562 distinct park names (PARK), 75 distinct facility names and 3 facility categories.
  • Data Type Issues:
    • The identifier columns OBJECTID_1, PARK_NO and GISOBJID use a non-breaking space as thousands separator (e.g. 1 111), which is why they import as text.
    • The coordinate columns (X_COORD, Y_COORD) use commas as decimal separators (e.g. -87,52486664).
  • Consistency Issues:
    • Several park numbers appear with more than one name. Most are spelling or formatting variants (MARQUETTE (jACQUES), PALMER ( POTTER), GATELY/GATLEY, MORAN (TERRANCE)/MORAN (TERRENCE)).
    • Some park numbers carry genuinely different parks: 19 (Jackson / Garfield), 168 (Matanky / Renaissance), 213 (Harrison / Stanton). Conversely, Garfield appears under 19 and 204, and Stanton under 109 and 213. Since Park URIs are built from PARK_NO, these rows must be checked and corrected manually.
    • the_geom duplicates X_COORD/Y_COORD, and the two disagree by more than 1 m in 66 rows (up to about 200 m).
    • GISOBJID is not a reliable identifier: it contains two 0 placeholders.
    • The FACILITY_N column has some rows with similar names that represent the same facility (e.g. FITNESS CENTER/FITNESS COURSE).
Column Type Comments / Range Problems
the_geom String (Point) Spatial point in WKT format, e.g. POINT (-87.6377 41.7630) Redundant with X_COORD/Y_COORD; differs from them by up to ~200 m in some rows.
OBJECTID_1 Integer Unique row identifier. Range 1 to 4,511 (44 gaps, so the maximum is not the row count). Non-breaking space as thousands separator. Needs cleanup and conversion to Integer.
PARK String Name of the park (562 distinct values for 549 park numbers) Case and spacing variants, misspellings, and a few genuinely different names under the same PARK_NO.
PARK_NO Integer Park identifier. Range 2 to 1,288; 549 distinct parks. Non-breaking space as thousands separator. Some numbers are shared by different parks.
FACILITY_N String Facility name (75 distinct values, e.g. PLAYGROUND, TENNIS COURT) 1 missing value (same row as the missing FACILITY_T).
FACILITY_T String Facility category: OUTDOOR (4,016), INDOOR (297), SPECIAL (153) 1 missing value.
X_COORD Float Longitude. Range -87.84 to -87.52 Uses comma (,) as decimal separator. Needs conversion to numeric.
Y_COORD Float Latitude. Range 41.65 to 42.02 Uses comma (,) as decimal separator. Needs conversion to numeric.
GISOBJID Integer Internal CPD GIS identifier. Range 1,428 to 6,810 Non-breaking space as thousands separator; 2 rows with placeholder 0.

1.2. Park Art Dataset

Each row is one public artwork (sculpture, mural, fountain, memorial, etc.) located in a park.

  • Quantities: 346 rows and 11 columns.
  • Null Values: Missing data in ARTIST (15 blanks), OWNER (53 blanks) and OFFICIAL_N (164 blanks).
  • Unique Values: 117 distinct park numbers (119 distinct park names), 325 distinct artwork names and 263 distinct artist values.
  • Data Type Issues:
    • As in the facilities data, PARK_NO and GISOBJID use a non-breaking space as thousands separator, and X_COORD/Y_COORD use commas as decimal separators. The same transformations apply.
  • Consistency Issues:
    • Artists: besides the 15 blanks, 10 rows contain the literal value "Unknown". 55 cells list several artists or a firm (e.g. Frederick & Elisabeth Hibbard, Adler & Sullivan), and the same person is sometimes written differently (Frederick C. Hibbard / Frederick Cleveland Hibbard). Some names contain characters that are not URI-safe (&, commas, ø).
    • Owners: the same organisation appears under several labels (CPD, City of Chicago, COC, City of Chicago & CPD), there are typos (On loan to Notebaert Musuem), and a few owners are individuals.
    • Artwork names: NAME is not unique ("Playground Art" appears 10 times, "Mosaic" 5 times), so it cannot be used in URIs. OFFICIAL_N is an optional formal title: identical to NAME in 122 rows and different in 60, so it is modelled as an alternative label.
    • Parks: a few park names vary under the same number (McKINLEY/MCKINLEY, LINCOLN/LINCOLN (ABRAHAM)), and King Park appears under both 265 and 334.
    • GISOBJID contains 38 placeholder 0 values.
Column Type Comments / Range Problems
the_geom String (Point) Spatial point in WKT format Redundant with X_COORD/Y_COORD; small differences (up to ~24 m).
OBJECTID Integer Unique row identifier. Range 1 to 354 (8 gaps) Imported as String by default. Needs conversion to Integer.
PARK String Name of the park (119 distinct values for 117 park numbers) Case variants and inconsistent naming under the same PARK_NO.
PARK_NO Integer Park identifier, shared with the facilities dataset. Range 4 to 1,270 Non-breaking space as thousands separator. Needs cleanup and conversion to Integer.
NAME String Name of the artwork (325 distinct values) Not unique: 27 rows share a name with another artwork.
X_COORD Float Longitude. Range -87.82 to -87.53 Uses comma (,) as decimal separator. Needs conversion to numeric.
Y_COORD Float Latitude. Range 41.67 to 42.02 Uses comma (,) as decimal separator. Needs conversion to numeric.
ARTIST String Name of the artist(s) (263 distinct values) 15 blanks and 10 "Unknown"; 55 multi-artist or firm cells; name variants; URI-unsafe characters.
OWNER String Owner entity (24 distinct values; CPD owns 231 artworks) 53 missing values; inconsistent labels and typos.
GISOBJID Integer Internal CPD GIS identifier. Range 1,231 to 6,777 Non-breaking space as thousands separator; 38 rows with placeholder 0. Not used as an identifier.
OFFICIAL_N String Official title of the artwork, when different or formalised 164 missing values; equal to NAME in 122 rows.

1.3. Relationship Between the Datasets

  • Join key: PARK_NO links both datasets. A park has many facilities and many artworks, so Park is the central entity of the graph.
  • Overlap: 111 of the 117 parks with art also appear in the facilities dataset. The other 6 (e.g. Ogden Plaza, Washington Square, Mid-North) only appear in the art data, so Park resources are generated from the union of both datasets: 555 distinct parks.
  • Name agreement: for 7 park numbers present in both datasets the names never match. Most are spelling variants (PETERSON (PAHR SAMUEL) / PETERSON (PEHR SAMUEL), GARIBALDI (GIUSEPPE) / GARIBALDI (GIUSEPPI)), but parks 115 and 265 carry completely different names and need manual review.

2. Licensing Analysis

  • Publisher: City of Chicago (Chicago Data Portal)
  • Rightsholder: Chicago Park District
  • Original License: The data portal provides the raw datasets under a "Public Domain" designation. However, their Terms of Use states that secondary applications utilizing modified data must feature a specific legal disclaimer acknowledging the City of Chicago as the source and disclaiming liability.
  • Proposed License: Because the source data is Public Domain, we will publish the generated RDF datasets under a Creative Commons Attribution 4.0 International (CC BY 4.0) license. This satisfies the requirement to credit the City of Chicago while allowing the data to be freely shared, linked, and adapted.

3. Resource Naming Strategy

  • Hash URIs for ontological terms, slash URIs for data individuals.
  • Ontological terms path: http://smartcity.chicago.es/ontology/ParkExplorer#
  • Individuals path: http://smartcity.chicago.es/resource/

3.1. URI Component Breakdown

Following the structural patterns defined in the methodology, the URIs are composed as follows:

Component Pattern Example
Class [ontologyName]#[className] .../ontology/ParkExplorer#ChicagoPark
Property [ontologyName]#[propertyName] .../ontology/ParkExplorer#hasFacility
Individual [className]/[identifier] .../resource/ChicagoPark/165

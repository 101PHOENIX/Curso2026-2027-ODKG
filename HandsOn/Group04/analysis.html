2. Data set analysis

2.1 D1 – Air quality, daily data 2024

Schema

The file uses a wide format: one row per station, pollutant and month, with 31 pairs of columns (Dxx value, Vxx validity flag), one per day of the month. The documentation says that daily files contain 28, 29, 30 or 31 day columns depending on the month, but the CSV always has 31 pairs and fills non-existent days with 0 / N.

Unlike the hourly files, the daily files do not have a DIA column: the day is given by the column suffix. Hourly data in the source is in Madrid local time, and the daily value is the mean of the hourly values (23 values on the day of the spring time change).

Quantities

  • 1,411 rows = 131 time series (one per sampling point) × up to 11 months.
  • 128 series cover January–November; 3 series (benzene, toluene and ethylbenzene at station 24) only appear in January.
  • 43,741 value cells: 42,273 flagged V and 1,468 flagged N. Of the N cells, 768 correspond to non-existent dates (e.g. 30 and 31 February), stored as 0;N, and 700 are real days with invalid measurements. Valid coverage over real days is therefore 98.4 %.
  • Rows per month: 131 in January, 128 in February–November. December 2024 is not present in the data set.

Data quality and transformation notes

  • Wide format. Each row has to be unpivoted into up to 31 daily observations (one per Dxx/Vxx pair). The date is built from ANO + MES + the column suffix.
  • Placeholder values. Non-existent dates contain 0 with flag N; they must be discarded, not converted to zero measurements.
  • Invalid values. 700 real-day values are flagged N. We keep the flag as a property of the observation instead of dropping the value silently.
  • Units are not in the file. They come from Annex II of the documentation (all µg/m³ except CO in mg/m³) and are added in the mapping.
  • Reasons for missing values. According to the documentation, values are missing or invalidated because of equipment maintenance, anomalous data removed during validation, or failures in power supply, communications or the analyser.
  • Station codes changed in 2010. Annex I shows that stations 35, 36, 38, 39 and 40 used codes 03, 20, 10, 05 and 13 until January 2010, to adapt to the national coding. This does not affect 2024 data, but matters if older years are added.
  • Redundant columns. PROVINCIA, MUNICIPIO and ANO are constant; the station and pollutant are also encoded inside PUNTO_MUESTREO.

Data quality and transformation notes

  • Three coordinate systems for the same point (DMS, UTM, decimal). We only use the decimal LATITUD/LONGITUD and drop the rest.
  • Non-uniform formats: UTM values use a decimal comma; the date is dd/mm/yyyy and must be converted to xsd:date; the column header Fecha alta contains a space; the file starts with a BOM.
  • Pollutant flags as columns. The seven X columns become a multi-valued "measures pollutant" relation. BTX groups three pollutants (benzene, toluene, ethylbenzene) and NO2 also implies NO and NOx in D1.
  • Inconsistency with D1: station 24 (Casa de Campo) reports BTX values in January 2024 but is not flagged as BTX in D2, consistent with the series stopping after January.
  • Commissioning date vs. code change: for stations 35, 36, 38, 39 and 40, Fecha alta (1998–1999) is the original start date, earlier than the 2010 code change shown in Annex I of D1.
  • Different station names across sources: D2 and Annex I of D1 use slightly different names (e.g. Barajas Pueblo vs Barajas, Juan Carlos I vs Parque Juan Carlos I). D2 is taken as the reference for labels.

Data quality and transformation notes

  • Missing district: 21 rows have the literal value DISTRITO as district name and 32 rows have no COD-DISTRITO (mostly facilities inside large parks). The district can be recovered from the coordinates with a point-in-polygon test against the official district boundaries.
  • Neighbourhood code is not global: COD-BARRIO (1–9) is only unique inside a district, so the neighbourhood identifier must combine both codes (e.g. district 21 + barrio 3 → 213).
  • Accessibility codes: 410 facilities (68 %) are coded as not accessible. The code is mapped to a small controlled list of accessibility levels instead of a bare number.
  • Unstable identifier: PK is an internal key of the municipal website, not an official facility code. It is the only unique identifier available, so we use it, but it could change if the website is migrated.
  • Coordinate error: one facility (Parque Forestal…) has longitude +3.641 instead of −3.641, placing it outside Spain; the sign is corrected during transformation.
  • Duplicated locations: 32 facilities share their exact coordinates with another one (several facilities in the same park).
  • Free text: EQUIPAMIENTO and TRANSPORTE mix several items in a single string; we keep them as literals rather than parsing them into resources.
  • Unused columns: 9 columns are empty or almost empty and are not mapped. TIPO is a portal path; only its last segment is used as the category.
  • Encoding: the original file on the portal (and the copy in csv/) is ISO-8859-1; it is converted to UTF-8 before the RDF transformation.

D3 is generated from the content of the municipal website www.madrid.es.

LicenceCreative Commons Attribution 4.0 International (CC BY 4.0), as stated in the portal's terms of use. Commercial and non-commercial reuse are allowed; the only obligation is to attribute the source. None of our three datasets is among the exceptions with extra conditions (library catalogue, EMT, Madrid Destino).
ObligationsCite the source (Ayuntamiento de Madrid), link to the licence, indicate if changes were made, and do not suggest that the City Council endorses our use.

External data: Wikidata is published under CC0 1.0, so linking to it and reusing its data adds no conditions.

3.2 Licence of the generated data set

We will publish both the ontology and the generated RDF data under CC BY 4.0:

  • CC BY 4.0 is a "BY" licence, so publishing under the same licence trivially satisfies the attribution obligation and keeps the data as open as the original.
  • A more restrictive licence (e.g. CC BY-SA or CC BY-NC) would be legally possible but would reduce reuse without any benefit; CC0 is not possible because we cannot waive the attribution required by the source.
  • The dataset metadata will include the attribution: "Contains data from the Madrid City Council open data portal (datos.madrid.es), CC BY 4.0. Data transformed into RDF by Group04."
  • The RDF transformation (unpivoting, unit annotation, spatial links, coordinate correction) is a change to the original data and will be stated in the metadata.

The licence and provenance will be declared in the dataset and ontology metadata:

4. Resource naming strategy

4.1 Domain

We use the w3id.org persistent identifier service as base domain:

https://w3id.org/breatheplay-madrid/
  • The URIs do not depend on where the data is hosted (GitHub Pages now, a triple store later): only the redirection rules in the w3id repository have to change.
  • The domain does not belong to the City Council, so we do not mint URIs in a domain we do not control.
  • HTTPS is used for all URIs.

4.2 Ontology URIs: hash

The ontology is small (around 10 classes and 30 properties), so it is served as a single document and its terms use hash URIs. One request returns the whole vocabulary.

ElementPatternExample
Ontologyhttps://w3id.org/breatheplay-madrid/ontologyprefix bpm: → https://w3id.org/breatheplay-madrid/ontology#
Version…/ontology/{major.minor.patch} (owl:versionIRI)…/ontology/1.0.0
Class…/ontology#{UpperCamelCase}bpm:MonitoringStation, bpm:SportsFacility, bpm:DailyObservation
Object property…/ontology#{lowerCamelCase verb}bpm:hasStation, bpm:measuresPollutant, bpm:hasNearestStation
Datatype property…/ontology#{lowerCamelCase}bpm:value, bpm:isValid, bpm:altitude

4.3 Data URIs: slash

Instances use slash URIs under /resource/, because there are tens of thousands of them and each one must be retrievable on its own. Patterns follow /resource/{type}/{id}, where {id} reuses the identifier from the source whenever one exists, so the URIs are stable and can be regenerated from the CSV.

4.4 Naming conventions

  • Language: English for all ontology terms; original Spanish names are kept as rdfs:label "…"@es, with English labels @en where useful.
  • Ontology terms: classes in UpperCamelCase and singular; properties in lowerCamelCase, starting with a verb (has…, is…, measures…).
  • Instance paths: type segments in lowercase kebab-case and singular; identifiers only with characters [a-z0-9_-], no accents or spaces.
  • Opaque, stable identifiers: source codes are used instead of names (station names or facility names can change; codes do not), so URIs never have to be renamed. For stations we use the current 8-digit national code; the codes that changed in 2010 can be kept as an extra literal property if older years are added. For facilities, PK is the only identifier available (see the note in 2.3).
  • Reuse of external URIs: pollutants and districts are linked to existing Wikidata entities with owl:sameAs, and standard vocabularies (e.g. SOSA/SSN, GeoSPARQL, dcterms) are reused where they fit, instead of redefining their terms.

4.5 Content negotiation

We follow the 303 See Other pattern for slash URIs: the resource URI identifies the real-world thing (a station, a court) and redirects to a document that describes it, in the format requested by the client in the Accept header.

Accept headerRedirect target (example for /resource/station/28079004)
text/html (browsers, default)/page/station/28079004
text/turtle/data/station/28079004.ttl
application/ld+json/data/station/28079004.jsonld
application/rdf+xml/data/station/28079004.rdf

For the ontology, https://w3id.org/breatheplay-madrid/ontology redirects to the HTML documentation (e.g. generated with WIDOCO) for browsers and to the .ttl file for RDF clients. Since the terms use hash URIs, the fragment is resolved on the client after retrieving the document. The rules are implemented in the .htaccess file of the w3id repository:

RewriteEngine on
# Ontology
RewriteCond %{HTTP_ACCEPT} text/turtle
RewriteRule ^ontology$ https://<group-pages>/ontology/breatheplay.ttl [R=303,L]
RewriteRule ^ontology$ https://<group-pages>/ontology/doc/index.html [R=303,L]
# Instances
RewriteCond %{HTTP_ACCEPT} text/turtle
RewriteRule ^resource/(.+)$ https://<group-pages>/data/$1.ttl [R=303,L]
RewriteCond %{HTTP_ACCEPT} application/ld\+json
RewriteRule ^resource/(.+)$ https://<group-pages>/data/$1.jsonld [R=303,L]
RewriteRule ^resource/(.+)$ https://<group-pages>/page/$1 [R=303,L]

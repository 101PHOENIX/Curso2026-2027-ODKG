1. Data analysis

What does the file contain?

The Deutsche Bahn (DB) delays dataset, published by Nokkyu on Kaggle, describes train schedules and delays at German stations. According to the publisher, the data comes from Deutsche Bahn’s Timetables and StaDa APIs, queried every hour from 8 to 14 July 2024.

Each row represents a train stop at a station, as recorded during collection. The same stop may appear several times, so the number of rows is not the number of trains.

The full file also contains 296 line labels and 1,292 city/locality labels, or 1,283 after trimming surrounding spaces. The CSV uses UTF-8, a comma separator and a header row.

Times may fall outside the collection dates, especially around midnight. The delay label means a delay of more than 5 minutes: 110,953 arrival records and 111,348 departure records. The remaining records are labelled on_time.

What needs cleaning or careful interpretation?

  • Missing data: keep the columns and rows. In RDF, omit the property for an empty cell. A missing scheduled arrival may indicate a starting station or unavailable information; the file cannot establish the cause.
  • Zero delays: all missing updated times have a reported delay of 0. This zero does not prove that the train was observed on time. Missing information does not establish a cancellation either.
  • Consistency: the delay equals updated time minus scheduled time for all 1,585,720 comparable arrivals and 1,721,431 departures. Seven updated arrivals have no scheduled arrival. Arrival–departure ordering has not been checked across the full file.
  • Duplicates: 6,725 rows are identical copies. There are 2,029,894 distinct IDs and 31,463 repeated occurrences; 24,738 of these differ from the first record with the same ID. The ID alone cannot identify every observation.
  • Text: trim city labels in 58,092 rows. Check the 115,126 four-digit postal codes before adding a leading zero. Preserve station order in path.
  • Dates: use ISO 8601 for RDF, for example 2024-07-08T00:00:00. No time zone is given, so do not add an arbitrary offset.

3. Resource naming

Principle

A URI is an identifier in the form of a web address. We separate ontology terms (such as the Station class) from individual resources (such as Aachen Hbf station).

The proposed base is https://example.org/db-delays/. This example domain differs from Protégé’s default domain.

Ontology classes and properties

Terms use the path ontology/#: the fragment after # identifies a class or property. Class names start with a capital letter; property names start with a lowercase letter.

TermExample URI
Class: stationhttps://example.org/db-delays/ontology/#Station
Class: recorded stophttps://example.org/db-delays/ontology/#TrainStop
Property: stop at a stationhttps://example.org/db-delays/ontology/#atStation
Property: arrival delayhttps://example.org/db-delays/ontology/#arrivalDelayMinutes

The ontology document URI is https://example.org/db-delays/ontology/. Properties are defined directly in the ontology namespace, rather than under a class URI.

Stations, stops, cities and states

Individuals use the path resource/, followed by their class. Add the paths below to the base https://example.org/db-delays/.

ResourceRuleExample path
Station (Station)Use the EVA identifier.resource/Station/8000001

Stop (TrainStop)Use the source ID and an observation number.resource/TrainStop/1573967790757085557-2407072312-14/observation/1

For repeated IDs: assign observation number 1 to the first record. A different row with the same ID receives number 2, then 3, and so on. An identical copy reuses the same number. Save this mapping with the original values and source version so later conversions reuse the same URIs.

Reuse the same station URI for the same EVA identifier. Clean names before creating URIs and encode special characters, for example Bad Homburg → Bad%20Homburg. A name correction must preserve the assigned URI.

The model links a stop to a station (atStation), a station to a city (inCity), and a city to a state (inState). Stations and cities can later be linked to Wikidata or DBpedia after verifying their identities.

What will a URI return?

When published, a request can ask for an HTML page for reading or Turtle for RDF data: this is content negotiation. For a station or stop, an HTTP 303 redirect will lead to its description. This is a proposed publication design; no service is deployed.

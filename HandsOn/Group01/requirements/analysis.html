Dataset Analysis, Licensing and Resource Naming Strategy

1. Dataset Analysis

1.1 Overview

The selected dataset is US_Accidents_New_York.csv, a subset of the "US Accidents (2016–2023)" dataset by Sobhan Moosavi, filtered to traffic accidents in New York City. The analysis below was performed over the complete CSV file using OpenRefine (text facets, numeric facets, facet by blank and timeline facet).

  • Rows: 21,699
  • Columns: 46
  • Time range (Start_Time): 2016-03-24 to 2023-03-31

2. Licensing Analysis

2.1 Publisher and rightsholder

The original dataset, "US Accidents (2016–2023)", was created and published by Sobhan Moosavi, a researcher who completed his PhD in Computer Science and Engineering at Ohio State University and currently works as a Scientist at Zoox (previously at Lyft). The dataset is distributed through the Kaggle platform, which acts only as a hosting platform and is not the rightsholder.

Sobhan Moosavi is therefore considered the publisher and rightsholder of the original dataset. The dataset is also linked to peer-reviewed academic publications co-authored by him, which are referenced on the dataset's Kaggle page as the recommended citation.

Source: US Accidents (2016–2023) - Kaggle

2.2 Original license

The original dataset is distributed under the Creative Commons Attribution-NonCommercial-ShareAlike 4.0 International (CC BY-NC-SA 4.0) license, which implies:

  • BY (Attribution): proper credit must be given to Sobhan Moosavi as the original author.
  • NC (NonCommercial): the dataset and any derivative work can only be used for non-commercial purposes.
  • SA (ShareAlike): any derivative work must be distributed under the same license as the original.

2.3 License for the generated dataset

Since the generated RDF dataset is derived from the original CSV, it will also be published under the Creative Commons Attribution-NonCommercial-ShareAlike 4.0 International (CC BY-NC-SA 4.0) license, with appropriate attribution to the original dataset.

3. Resource Naming Strategy

3.1 Base domain

A custom domain (not the Protégé default) is used as the base namespace for this project: 

http://group01.opendata.upm.es/

3.2 Namespaces

Two separate namespaces are defined under the base domain: one for the ontology terms (classes and properties) and one for the data (individuals). This separation is intentional, so that ontology resources and individual resources never share the same path.

NamespaceURIPrefixUsed for
Ontology http://group01.opendata.upm.es/ontology/accidents# ao: Classes and properties (the vocabulary)
Data http://group01.opendata.upm.es/resource/ resource: Individuals (instances of the ontology classes)

A # (hash) is used for ontology terms and a / (slash) is used for data resources, which is a common convention to distinguish a vocabulary from the dataset that uses it.

3.3 URI patterns for individuals

Each class of individual is assigned its own path segment under /resource/, so that individuals of different classes never share the same path, and so that an individual's URI never depends on its class URI:

ClassPath patternExample
ao:TrafficAccident /resource/accidents/{ID} http://group01.opendata.upm.es/resource/accidents/A-194408
ao:Street /resource/streets/{slug} http://group01.opendata.upm.es/resource/streets/E-74th-St

The {ID} for accidents reuses the dataset's own unique identifier (e.g. A-194408). The {slug} for streets is derived from the street name, replacing spaces with hyphens (e.g. "E 74th St" → E-74th-St). The ao:Street class is also the class used to link accident data to other entities, since street names can be aligned with external geographic datasets (e.g. Wikidata, OpenStreetMap).

3.4 Content negotiation

Although no server is actually deployed for this assignment, the naming strategy is designed to support content negotiation: a resource URI such as http://group01.opendata.upm.es/resource/accidents/A-194408 would respond with a 303 See Other redirect to a representation-specific URI depending on the Accept header of the request:

  • Accept: text/html → /resource/accidents/A-194408.html (human-readable page)
  • Accept: text/turtle → /resource/accidents/A-194408.ttl (RDF/Turtle)
  • Accept: application/ld+json → /resource/accidents/A-194408.jsonld (JSON-LD)

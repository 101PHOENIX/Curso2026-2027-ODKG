01 · Source Data

Dataset Overview

The dataset analyzed here represents a complete snapshot of service requests filed within the City of Los Angeles in 2025.

Note on Analysis Scope: Due to GitHub memory constraints and the sheer volume of the data, this comprehensive profiling was executed locally via a Python script directly on the full 423,053-row CSV file. This contrasts with the uploaded lightweight dataset, which is a truncated sample designed specifically for web performance and quick graphical previews.

02 · Legal Framework

Licensing Analysis

Establishing a clear licensing framework is crucial for opening our knowledge graph to researchers, journalists, and civic developers. Because the original service request dataset is released into the public domain, we are entirely free to apply a new open license to our derived semantic models and applications.

Motivations for our chosen license

We have chosen to license the LA 311 Fieldnotes knowledge graph and SPARQL endpoint under CC BY 4.0 (Creative Commons Attribution 4.0 International). This aligns directly with our application's non-functional requirements and FR5, which strictly mandates displaying source attribution.

By applying CC BY 4.0, we ensure that everyone can freely query our SPARQL endpoint, share, adapt, and even commercialize our mapped materials. In return, users must attribute our group for the semantic modeling and Linked Data generation, while continuing to acknowledge the City of Los Angeles as the authoritative source of the raw civic data.

Source Data Licensing

  • Publisher: City of Los Angeles - Information Technology Agency (via DataLA)
  • Rightsholder: City of Los Angeles
  • License: CC0 1.0 Universal (Public Domain Dedication). This promotes transparency and encourages free usage, analysis, and application development without copyright restrictions.

Project Licensing

  • License Applied: CC BY 4.0
  • Condition: Requires proper attribution for our derived semantic work, while preserving the acknowledgment of the City of Los Angeles as the source.

04 · Resource Naming

Resource Naming Strategy

To ensure consistency, interoperability, and alignment with Linked Data best practices, the LA 311 Fieldnotes knowledge graph follows a well-defined resource naming strategy. It separates the vocabulary (ontology) from the actual dataset instances (resources) using distinct HTTP paths.

Base Namespace

All resources are minted under a dedicated domain controlled by our project, distinct from standard application defaults:

http://linkeddata.la311.com

1 · Ontology URIs (Vocabulary)

Path: http://linkeddata.la311.com/ontology#

We use hash URIs for defining classes and properties so the entire lightweight vocabulary can be retrieved in a single HTTP request. They match our exported schema exactly:

  • Classes (UpperCamelCase):
    .../ontology#ServiceRequest
    .../ontology#Organization
    .../ontology#AdministrativeRegion
  • Properties (lowerCamelCase):
    .../ontology#hasLocation (object)
    .../ontology#isWithin (object)
    .../ontology#srNumber (datatype)
    .../ontology#createdDate (datatype)

2 · Data URIs (Individuals)

Path: http://linkeddata.la311.com/resource/

We use slash URIs for the generated data instances, mapping them directly to their class and a unique dataset identifier:

  • Service Requests → .../resource/ServiceRequest/{SRNumber}
    e.g. .../resource/ServiceRequest/1-5167495871
  • Organizations → .../resource/Organization/{Nome}
    e.g. .../resource/Organization/LASAN
  • Administrative Regions → .../resource/AdministrativeRegion/{NC}_{CD}
    e.g. .../resource/AdministrativeRegion/50_14
  • Locations → .../resource/Location/{Latitude},{Longitude}
    e.g. .../resource/Location/34.0579,-118.2759

3 · Content Negotiation

Because Data URIs identify real-world concepts (like a physical civic issue or a department), we use 303 See Other HTTP redirects to resolve them based on the requesting client:

  • Human Request (Accept: text/html): Server redirects to an HTML page (e.g., /page/ServiceRequest/1234567) displaying the ticket details.
  • Machine Request (Accept: application/rdf+xml): Server redirects to a data document (e.g., /data/ServiceRequest/1234567) containing the raw semantic triples.

4 · External Linking Strategy

To integrate our local knowledge graph with the broader Linked Open Data cloud, specific classes have been designated to link our data instances to external authoritative entities (such as Wikidata, DBpedia, or GeoNames) using owl:sameAs:

  • la311:AdministrativeRegion: Civic and geographic instances, such as specific Neighborhood Councils (e.g., Boyle Heights) or Police Precincts, will be linked to their corresponding geographic entities in Wikidata.
  • la311:Organization: Instances representing Los Angeles city departments (e.g., LASAN, BSL) will link to their official Wikidata or DBpedia public agency records.
  • la311:Location: Verified geographic identifiers, such as ZIP Codes, will link to external geographical databases like GeoNames.

SafeRoute Madrid - Data Analysis

1. Data Source Analysis

1.1 Dataset Description

The selected datasets contain detailed information about traffic accidents registered in the city of Madrid during 2025 and 2026. The datasets are published through the Madrid City Council Open Data Portal and belong to the transportation domain.

The 2025 dataset contains 51,067 records covering the period from 1 January 2025 to 31 December 2025. The 2026 dataset currently contains 30,457 records covering the period from 1 January 2026 to 31 July 2026.

Both datasets follow the same schema and contain 19 attributes. This makes it possible to process information from both years using the same data model.

These datasets will be used for the SafeRoute Madrid application. The objective of the application is to use historical accident information to identify accident-prone locations and warn users when a calculated route passes through areas with a higher accident risk.

1.2 Data Format

The selected datasets are provided in CSV format. The use of a structured tabular format makes it possible to identify the schema, analyse the values of individual attributes and transform the data into RDF in later stages of the Linked Data generation process.

1.3 Dataset Schema

Both datasets contain the following 19 attributes:

  • num_expediente: identifier of the accident record.
  • fecha: date of the accident.
  • hora: time of the accident.
  • localizacion: location or street where the accident occurred.
  • numero: street number associated with the location.
  • cod_distrito: numerical code identifying the Madrid district.
  • distrito: name of the Madrid district.
  • tipo_accidente: type of traffic accident.
  • estado_meteorológico: weather conditions at the time of the accident.
  • tipo_vehiculo: type of vehicle involved.
  • tipo_persona: role of the person involved in the accident.
  • rango_edad: age range of the person involved.
  • sexo: sex of the person involved.
  • cod_lesividad: code representing injury severity.
  • lesividad: description of injury severity.
  • coordenada_x_utm: X coordinate of the accident location in UTM coordinates.
  • coordenada_y_utm: Y coordinate of the accident location in UTM coordinates.
  • positiva_alcohol: indicates whether alcohol involvement was detected.
  • positiva_droga: indicates whether drug involvement was detected.

1.4 Analysis of Values and Ranges

The values contained in the datasets were analysed in order to understand their ranges and the main categories that will need to be represented during the generation of Linked Data.

Accident Types

Both datasets contain 13 different accident categories. Examples include front-lateral collision, rear-end collision, lateral collision, collision with a fixed obstacle, pedestrian collision, multiple collision, fall, frontal collision, vehicle leaving the road, rollover and collision with an animal.

The most frequent accident type in both datasets is "Colisión fronto-lateral". Other particularly frequent categories include "Alcance" and "Colisión lateral".

Weather Conditions

Seven non-null weather categories appear in the datasets. These include clear weather, cloudy weather, light rain, heavy rain, snow and hail, as well as cases where the weather is unknown.

"Despejado" is the most frequent recorded weather condition in both datasets. Some records do not contain a weather value, which must be considered when transforming the source data.

Vehicle Types

The datasets contain a large variety of vehicle categories. The 2025 dataset contains 32 different non-null vehicle types, while the 2026 dataset contains 30.

These include passenger cars, vans, motorcycles, buses, rigid trucks, bicycles, all-terrain vehicles, electric personal mobility vehicles, mopeds and other specialised vehicle types. "Turismo" is the most frequently represented vehicle category in both datasets.

Person Types

The principal person categories are drivers, passengers and pedestrians. Drivers represent the largest category in both datasets.

Age Ranges

The datasets contain 18 age-range categories. They cover children, teenagers and adults through to people over 74 years old. An additional "Desconocido" category is used where the age range is unknown.

Sex

Three values are used for the sex attribute: Hombre, Mujer and Desconocido.

Districts

The cod_distrito attribute contains 21 distinct district codes, corresponding to the 21 districts of Madrid. The district information is particularly useful for linking the accident dataset with external geographical data.

Alcohol and Drug Indicators

The positiva_alcohol field uses "S" and "N" values to indicate positive and negative alcohol results, although some records have no value.

The positiva_droga field is much more sparsely populated. Positive cases are represented with the value 1, while most records have no value in this field.

1.5 Relevant Entities and Relationships

From the analysis of the datasets, several relevant entities can be identified for the SafeRoute Madrid ontology. These include TrafficAccident, District, Location, Vehicle and Person.

A TrafficAccident occurs at a Location and within a District. An accident can involve one or more Vehicles and Persons. Characteristics such as accident type, weather conditions, date and time describe the accident, while attributes such as age range, sex and injury severity describe people involved in it.

These entities and relationships will form the basis of the lightweight ontology developed for the project.

1.6 Linking Possibilities

The datasets contain several attributes that make the generated resources suitable for linking with external real-world entities.

In particular, cod_distrito and distrito can be used to identify Madrid districts. The localizacion attribute and UTM coordinates can be used to identify geographical locations associated with accidents.

These resources could therefore be linked with other datasets describing Madrid districts, streets and geographical entities. This is especially relevant for SafeRoute Madrid because geographic information is required to identify accident-prone locations and analyse accident risk along a calculated route.

2. Licensing Analysis

2.1 Publisher and Responsible Organisation

The traffic accident datasets are published through the Madrid City Council Open Data Portal. The dataset metadata identifies the General Directorate of the Municipal Police as responsible for the dataset.

2.2 License of the Source Data

The Madrid City Council Open Data Portal identifies the license of the selected traffic accident dataset as Creative Commons Attribution 4.0 International (CC BY 4.0).

This license permits the material to be shared and adapted, provided that appropriate attribution is given to the original source. Therefore, the data can be reused for the SafeRoute Madrid Linked Data project while respecting the attribution requirement.

2.3 Potential License of the Generated Dataset

The proposed license for the Linked Data generated by the SafeRoute Madrid project is Creative Commons Attribution 4.0 International (CC BY 4.0).

This maintains the attribution requirement associated with the original Madrid City Council dataset and allows the generated dataset to be openly reused.

3. Resource Naming Strategy

A resource naming strategy is defined to provide consistent, persistent and meaningful URIs for both the ontology terms and the individual resources generated from the datasets.

3.1 URI Form

Hash URIs will be used for ontology classes and properties, while slash URIs will be used for individual resources. This provides a clear separation between the ontology model and the instances generated from the datasets.

3.2 Domain

The following domain will be used as the base for the resource naming strategy:

https://w3id.org/saferoutemadrid/

3.3 Ontology Path and Pattern

The classes and properties defined in the SafeRoute Madrid ontology will use the following namespace:

https://w3id.org/saferoutemadrid/ontology#

The ontology includes the main classes TrafficAccident, Person, Vehicle, Location and District. It also includes controlled-vocabulary classes, such as AccidentType, WeatherCondition, VehicleType, PersonType, AgeRange, Sex and InjurySeverity.

Examples of ontology terms are:

  • https://w3id.org/saferoutemadrid/ontology#TrafficAccident
  • https://w3id.org/saferoutemadrid/ontology#District
  • https://w3id.org/saferoutemadrid/ontology#Location
  • https://w3id.org/saferoutemadrid/ontology#Vehicle
  • https://w3id.org/saferoutemadrid/ontology#Person
  • https://w3id.org/saferoutemadrid/ontology#occursAt
  • https://w3id.org/saferoutemadrid/ontology#locatedIn
  • https://w3id.org/saferoutemadrid/ontology#involvesPerson
  • https://w3id.org/saferoutemadrid/ontology#involvesVehicle
  • https://w3id.org/saferoutemadrid/ontology#hasAccidentType
  • https://w3id.org/saferoutemadrid/ontology#hasWeatherCondition

3.4 Individual Resource Path and Pattern

Individual resources generated from the datasets will use slash URIs under the resource path. Whenever possible, identifiers from the original source datasets will be used to construct the individual resource URIs. For example the identifier for a traffic accident could be the num_expediente column from the dataset. This makes the generated Linked Data easier to relate to the original data. Examples of these URIs are:

  • Traffic Accident: https://w3id.org/saferoutemadrid/resource/TrafficAccident/{num_expediente}
  • District: https://w3id.org/saferoutemadrid/resource/District/{cod_distrito}
  • Location: https://w3id.org/saferoutemadrid/resource/Location/{identifier}
  • Vehicle: https://w3id.org/saferoutemadrid/resource/Vehicle/{identifier}
  • Person: https://w3id.org/saferoutemadrid/resource/Person/{identifier}

The controlled-vocabulary classes are represented as SKOS concepts because they contain predefined categories used to describe the resources in the dataset.

For example, VehicleType has concepts such as Car or Motorcycle and they can be identified using URIs such as:

https://w3id.org/saferoutemadrid/resource/VehicleType/Car

In this way, an actual vehicle resource can be linked to a predefined category. For example, Vehicle/123 can have the property hasVehicleType pointing to VehicleType/Car.

3.5 Naming Conventions

Classes use capitalized names written in CamelCase, such as TrafficAccident, Location, VehicleType and InjurySeverity.

Properties start with a lowercase letter and use meaningful names, such as occursAt, locatedIn, involvesPerson, involvesVehicle, hasAccidentType and accidentDate.

Datatype properties follow the same naming convention. Examples include accidentDate, accidentTime, streetName, streetNumber, districtCode, positiveAlcohol, positiveDrug and accidentID.

3.6 Content Negotiation

The URI strategy makes it possible to access the published resources directly through their URIs. Content negotiation can be used so that clients requesting RDF receive an RDF representation, while web browsers can receive an HTML representation of the resource.

1.4. General Observations

The three datasets share information about sports centres, which will later allow their records to be connected. However, centre names should first be normalised and reconciled because the same real-world facility may not always be represented using exactly the same string in every dataset.

3. Define Resource Naming Strategy

3.1. Base domain

The proposed base domain for the project is: 

https://w3id.org/active-madrid/

The use of a persistent namespace such as w3id.org helps to avoid depending on a temporary local domain and provides a stable base for the URIs.

3.2. URI form

Two different URI forms will be used:

  • Hash URIs for ontology terms such as classes and properties.
  • Slash URIs for data resources contained in the datasets.

The ontology namespace will be: 

https://w3id.org/active-madrid/ontology#

The base URI for data resources will be: 

https://w3id.org/active-madrid/resource/

3.3. Ontology URI patterns

Classes and properties defined specifically for Active Madrid will share the ontology namespace but will follow different naming conventions.

Resource type Pattern Example
Class https://w3id.org/active-madrid/ontology#[ClassName] https://w3id.org/active-madrid/ontology#SportsClass
Property https://w3id.org/active-madrid/ontology#[propertyName] https://w3id.org/active-madrid/ontology#availablePlaces

3.4. Data URI patterns

Data resources will use slash URIs. The type of the resource will form part of the path so that resources belonging to different classes have different URI patterns.

Resource type Pattern Example
Sports facility https://w3id.org/active-madrid/resource/SportsFacility/[identifier] https://w3id.org/active-madrid/resource/SportsFacility/12345
Sports class https://w3id.org/active-madrid/resource/SportsClass/[identifier] https://w3id.org/active-madrid/resource/SportsClass/98765
Sport activity https://w3id.org/active-madrid/resource/SportActivity/[identifier] https://w3id.org/active-madrid/resource/SportActivity/swimming
District https://w3id.org/active-madrid/resource/District/[identifier] https://w3id.org/active-madrid/resource/District/retiro

3.5. Naming conventions

  • Class names defined in the Active Madrid ontology will start with a capital letter and use UpperCamelCase, for example SportsFacility, SportsClass, SportActivity and District.
  • Properties defined in the Active Madrid ontology will start with a lowercase letter and use lowerCamelCase, for example availablePlaces, occupiedPlaces, takesPlaceAt and locatedInDistrict.
  • Resource identifiers should be stable and should not contain information that may change over time.
  • Whenever an identifier already exists in the original dataset, such as the identifier of a sports facility, it should be preferred over a label or name when constructing its URI.

3.6. Reuse of existing vocabularies

The Active Madrid ontology will follow a hybrid approach. Existing standard vocabularies will be reused whenever they provide an appropriate semantic representation. New Active Madrid terms will only be created for concepts and relationships that are specific to the selected datasets.

The following vocabularies are considered for reuse:

Vocabulary Prefix Purpose in Active Madrid Examples
Schema.org schema: Representation of sports facilities, addresses, names and contact information. schema:SportsActivityLocation, schema:PostalAddress, schema:name, schema:address, schema:telephone, schema:email
WGS84 Geo Positioning geo: Representation of the geographical coordinates of sports facilities. geo:lat, geo:long
OWL-Time time: Representation of temporal information associated with sports classes, such as their starting and ending times. time:Interval, time:Instant, time:hasTime, time:hasBeginning, time:hasEnd
Dublin Core Metadata Elements dc: Description of ontology metadata such as its creator and title. dc:creator, dc:title
MOD (Metadata for Ontology Description) mod: Description of metadata about the ontology development process. mod:createdWith
OWL owl: Definition of the ontology, classes, properties and restrictions. owl:Ontology, owl:Class, owl:ObjectProperty, owl:DatatypeProperty, owl:Restriction, owl:versionInfo
RDF Schema rdfs: Definition of labels, class hierarchies, domains and ranges. rdfs:label, rdfs:subClassOf, rdfs:domain, rdfs:range
XML Schema Datatypes xsd: Definition of datatypes for literal values. xsd:string, xsd:nonNegativeInteger, xsd:decimal, xsd:dateTime

In addition to vocabularies used to model the domain data, the ontology also reuses Dublin Core and MOD for ontology metadata, OWL for the formal definition of classes, properties and restrictions, and RDFS for labels, subclass relationships, domains and ranges.

3.7. Hybrid ontology conceptualization

The ontology combines reused concepts from existing vocabularies with a small number of terms created specifically for Active Madrid.

The central resource is a sports class. A sports class represents an activity offered at a particular sports facility and contains information about its capacity, availability and schedule.

Concept Representation Origin Description
Sports class am:SportsClass Active Madrid A particular sports class or activity offering contained in the classes datasets.
Sports facility am:SportsFacility
subclass of schema:SportsActivityLocation 		Active Madrid + Schema.org A municipal facility where sports activities take place.
Sport activity am:SportActivity Active Madrid A type of sport or activity, such as swimming, tennis or judo.
District am:District Active Madrid A district of Madrid in which a sports facility is located.
Address schema:PostalAddress Schema.org Structured address information associated with a sports facility.
Geographical coordinates geo:lat, geo:long WGS84 Latitude and longitude of a sports facility.
Schedule time:Interval OWL-Time Temporal interval describing when a sports class starts and ends.

Active Madrid properties

Only properties that cannot be adequately represented using the reused vocabularies are defined in the Active Madrid namespace.

Property Type Domain Range Description
am:takesPlaceAt Object property am:SportsClass am:SportsFacility Links a sports class to the facility where it takes place.
am:hasActivity Object property am:SportsClass am:SportActivity Associates a sports class with its sport or activity.
am:locatedInDistrict Object property am:SportsFacility am:District Links a sports facility to the district where it is located.
am:offeredPlaces Datatype property am:SportsClass xsd:nonNegativeInteger Total number of places offered for the class.
am:occupiedPlaces Datatype property am:SportsClass xsd:nonNegativeInteger Number of places currently occupied.
am:availablePlaces Datatype property am:SportsClass xsd:nonNegativeInteger Number of places currently available.

Other information will reuse existing Schema.org properties whenever possible. For example, the name of a facility will use schema:name, its address will use schema:address, its telephone number will use schema:telephone, and its email will use schema:email.

The geographical position of a sports facility will be represented using the WGS84 vocabulary through geo:lat and geo:long, reusing directly the latitude and longitude values available in the dataset.

Temporal information can be associated with a sports class using time:hasTime and represented through time:Interval, time:hasBeginning and time:hasEnd.

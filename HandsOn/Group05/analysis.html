1.4 Data quality issues found

  • Date and hour are split. Fecha always contains midnight and the actual hour is in Hora, without a leading zero. Both columns must be combined into a single xsd:dateTime value (e.g., 2020-01-01T13:00:00) before generating RDF.
  • Missing values have two different causes. Most empty cells are structural: the station does not have that sensor (for example, CO is only measured at 6 stations, and the benzene/toluene/xylene/noise columns only at Pista Silla). The rest are real gaps in a sensor that normally measures. 83,605 rows have no pollutant value at all; 70,152 of them belong to the two meteorological stations. Empty cells will not generate any observation; they must never be converted into zeros.
  • Incomplete series. Several stations do not cover the whole period: Valencia Centro starts in January 2018, Puerto Valencia covers only 2017–2020, Nazaret Meteo starts in 2020, and the two new port stations only cover 2021 (Puerto llit antic Túria has values for less than half of its hours). Molí del Sol has 43,848 rows instead of 52,608.
  • Out-of-range values. 63 relative humidity values are above 100% (maximum 107%), 198 solar radiation values are negative (minimum -7 W/m2) and 60 noise values are above 140 dB(A) (maximum 250), while 99% of noise values are below 73 dB(A). These values are physically implausible and will be flagged during data preparation (Assignment 3).
  • Redundant columns. Día de la semana and Día del mes can be derived from the date and will not be transformed.
  • No identifiers for stations. Stations are identified only by their name, which contains spaces, accents and abbreviations (e.g., Puerto Moll Trans. Ponent). Identifiers for stations will therefore have to be derived from their names.
  • Column headers in Spanish. Headers mix chemical formulae (NO2) and Spanish names (Temperatura, Ruido). The ontology will need English labels for them, and the original header can be kept as the code of each measured magnitude.

The analysis shows that the dataset contains 12 stations and 22 measured magnitudes, more than the 5 stations and 8 pollutants identified in Assignment 1 from the portal description.

3. Resource naming strategy

3.1 URI form

  • Ontology terms: hash URIs. The ontology is small (a few classes and properties), rarely changes and is always retrieved as a whole, so a single HTTP GET on the ontology URI returns every term.
  • Individuals: slash URIs. The dataset is large: 449,026 hourly records from 12 stations, with 6,037,812 non-empty measured values, each of which becomes an observation. Slash URIs allow every resource to be retrieved individually or in groups, without downloading the whole dataset.

3.2 Domain

All resources are published under https://w3id.org/valencia-airquality/. We use the w3id.org permanent identifier service so that the URIs are persistent and do not depend on the server that hosts the data: if the hosting changes, only the w3id redirection rules have to be updated, never the URIs. This domain is different from the default IRI assigned by Protégé (http://www.semanticweb.org/...).

3.3 Paths

ResourcesPathBase URI
Ontology (classes and properties)ontology/airquality#https://w3id.org/valencia-airquality/ontology/airquality#
Individuals (data)resource/https://w3id.org/valencia-airquality/resource/

Ontology terms and individuals are kept under different paths, so the ontology model is separated from its instances.

3.4 Patterns

ResourcePatternExample
Classhttps://w3id.org/valencia-airquality/ontology/airquality#[ClassName]https://w3id.org/valencia-airquality/ontology/airquality#MonitoringStation
Propertyhttps://w3id.org/valencia-airquality/ontology/airquality#[propertyName]https://w3id.org/valencia-airquality/ontology/airquality#hasStation
Individualhttps://w3id.org/valencia-airquality/resource/[ClassName]/[identifier]https://w3id.org/valencia-airquality/resource/MonitoringStation/AvdaFrancia
  • Class names use UpperCamelCase and property names use lowerCamelCase. All terms are named in English.
  • Property URIs are defined directly in the ontology namespace and do not depend on any class URI (#hasStation, not #MonitoringStation/hasStation).
  • Individual URIs are defined under resource/ and not derived from the class URIs of the ontology. The class name is only used as a path segment, so that individuals of different classes never share the same path.

Patterns for the individuals generated from the dataset:

3.5 Rules for building identifiers

  • [station]: the value of Estación without accents, spaces or punctuation, in UpperCamelCase (see table below).
  • [yyyyMMdd]T[HHmm]: the date of Fecha combined with Hora; the hour is padded to two digits (2020-01-01T00:00:00 + 13:00:00 → 20200101T1300).
  • [magnitude]: the column header; chemical formulae are kept, characters that are not valid in a URI path are replaced by _ and Spanish names are translated into English UpperCamelCase (see table below).
  • No observation URI is created for an empty cell, so missing values are never represented as zeros.
  • Identifiers depend only on the data (station, date, hour and magnitude) and never on state information, so running the transformation again always produces the same URIs.

3.6 Content negotiation

Every individual URI identifies a real-world thing (a station, an observation), not a document. When it is dereferenced, the w3id redirection rules answer with 303 See Other and redirect according to the Accept header of the request:

RequestRedirected to
Accept: text/htmlhttps://w3id.org/valencia-airquality/page/[ClassName]/[identifier] (human-readable page)
Accept: text/turtle or application/rdf+xmlhttps://w3id.org/valencia-airquality/data/[ClassName]/[identifier] (RDF description)

The ontology URI https://w3id.org/valencia-airquality/ontology/airquality returns the HTML documentation of the ontology for text/html and the Turtle file for text/turtle. Because ontology terms use hash URIs, the fragment is removed by the client and the whole ontology is returned.

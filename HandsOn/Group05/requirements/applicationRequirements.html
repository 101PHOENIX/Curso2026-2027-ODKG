1. Application overview

València Air Quality Explorer is a web application that allows citizens, researchers and municipal staff to explore the historical evolution of air quality in the city of València between 2016 and 2021. The application combines hourly measurements from the monitoring stations of the Red Valenciana de Vigilancia y Control de la Contaminación Atmosférica (RVVCCA) with the geographic location and metadata of each station, published as separate datasets by the Ajuntament de València.

The added value of the Linked Data approach is that pollutant observations, monitoring stations and real-world locations are represented as interlinked resources, which makes it possible to answer questions that cannot be answered from the original CSV alone.

2. Competency questions

The application is designed to answer the following questions:

  • CQ1. What was the average concentration of NO2 at a given station during a given month?
  • CQ2. Which station recorded the highest PM10 levels in a given year?
  • CQ3. How did O3 concentrations evolve between 2016 and 2021 across all stations?
  • CQ4. Which stations exceeded the WHO recommended thresholds, and how often?
  • CQ5. Is there a correlation between wind speed and pollutant concentration at a station?
  • CQ6. Which stations are located closest to a given point of interest in the city?

3. Functional requirements

  • FR1. The user can select one or more monitoring stations.
  • FR2. The user can select one or more pollutants (SO2, CO, NO, NO2, NOx, O3, PM10, PM2.5).
  • FR3. The user can restrict the analysis to a time range (year, month, day, hour).
  • FR4. The application displays the selected stations on an interactive map.
  • FR5. The application displays the time series of the selected pollutants as a line chart.
  • FR6. The application displays summary statistics (mean, maximum, minimum, number of valid readings).
  • FR7. The application highlights readings that exceed legal or recommended thresholds.
  • FR8. The user can export the current selection as CSV and as RDF.

4. Non-functional requirements

  • NFR1. The application queries the data through a SPARQL endpoint.
  • NFR2. The interface is available in English and Spanish.
  • NFR3. Missing values are shown explicitly and are never silently treated as zero.
  • NFR4. Every view displays the attribution required by the CC BY 4.0 licence.
